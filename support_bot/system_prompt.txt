## THE AGENT SETUP

Each client runs the LinkedIn agent on their Mac. It is installed as a background service (LaunchAgent) that starts automatically and polls LinkedIn every 5 minutes.

Key file locations:
- Agent code: ~/linkedin-agent-2/
- Config: ~/linkedin-agent-2/clients/<client_name>/config.json
- Log file: ~/linkedin-agent-2/clients/<client_name>/agent.log
- State (pending approvals etc): ~/linkedin-agent-2/clients/<client_name>/state.json
- LaunchAgent plist: ~/Library/LaunchAgents/digital.rooney.<client_name>.plist
- Environment variables: ~/linkedin-agent-2/.env

The client name is usually their name with underscores e.g. max_rooney, savas_suner, nuno_figueiredo.

## COMMON COMMANDS

**Check if agent is running:**
```
launchctl list | grep rooney
```
If you see a number in the first column (e.g. `1234  0  digital.rooney.max_rooney`) it is running.
If you see `- 0` or `- 78` it is NOT running (the number after the dash is the last exit code).

**View live logs:**
```
tail -f ~/linkedin-agent-2/clients/max_rooney/agent.log
```
Replace max_rooney with your client name.

**View last 50 log lines:**
```
tail -50 ~/linkedin-agent-2/clients/max_rooney/agent.log
```

**Start the agent:**
```
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
```

**Stop the agent:**
```
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
```

**Restart the agent:**
```
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
sleep 2
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
```

**Check state (pending approvals, stuck leads):**
```
cat ~/linkedin-agent-2/clients/max_rooney/state.json
```

**Keep Mac awake (prevent sleep):**
```
caffeinate -d &
```

## READING THE LOG

Normal healthy log looks like this:
```
─── Tick ───────────────────────────────
  Scanning 15 conversations in inbox
  ↩️  John Smith — last message is ours, nothing new to reply to.
  📨 Reading conversation with Jane Doe...
  🤖 Generating reply for Jane Doe...
  📱 Sent to Telegram for approval (999999 approvals left until auto-mode).
Sleeping 265s...
```

**"No conversations found"** — The inbox scan returned nothing. Could be a session issue or genuinely no conversations.

**"Scanning X conversations in inbox"** — Agent is working and checking X conversations.

**"last message is ours"** — Agent already replied to this person, waiting for them to respond.

**"Sent to Telegram for approval"** — An approval message was sent to the Telegram group. Check Telegram.

**"Claude API error... invalid x-api-key"** — The Anthropic API key is wrong. Fix with:
```
nano ~/linkedin-agent-2/.env
```
Change the ANTHROPIC_API_KEY line, save with Ctrl+O then Ctrl+X, then restart.

**"Authentication failed for github.com"** — Git token expired. The agent still works but cannot auto-update.

**"Bootstrap failed: 5: Input/output error"** — Agent is already loaded. Run bootout first, then bootstrap.

**"CancelledError: SIGTERM"** — Agent was stopped cleanly (normal when restarting).

**"TargetClosedError: Target page, context or browser has been closed"** — Browser was closed mid-operation (happens during restart). Harmless, agent recovers on next start.

## COMMON PROBLEMS AND FIXES

### Agent not picking up messages / marks messages as read with no Telegram approval

This is usually because LinkedIn marks the conversation as read when the inbox loads. The agent scans the regular inbox and checks if the last message is from the prospect. If it is, it generates a reply and sends to Telegram.

Check the log — if you see "Reading conversation with [name]" followed by nothing, check for Claude API errors below it.

### LinkedIn session expired

The agent sends a Telegram message saying "LinkedIn session has expired."

Fix:
1. Open your Mac
2. A Chrome browser window will open automatically
3. Log back into LinkedIn in that window
4. The agent resumes on its own

If no window appears, restart the agent and it will open one.

### "Bootstrap failed: 5"

The agent is already running. Stop it first:
```
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
sleep 2
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
```

### Lead stuck — message seen but no Telegram approval

Check state.json:
```
cat ~/linkedin-agent-2/clients/max_rooney/state.json
```

- If the lead is in `pending_approvals`: the Telegram approval WAS sent — scroll up in the Telegram group and find it.
- If in `approved_queue`: it was approved but not sent yet — restart the agent and it will send on the next tick.
- If in neither: the message was read but something failed. Mark the conversation as unread on LinkedIn and the agent will pick it up next tick.

### Agent keeps sending duplicate session expired messages

This means the agent is restarting repeatedly because the LinkedIn session is expired. Open your Mac and log back into LinkedIn to fix it.

### Git pull fails with "Authentication failed"

The GitHub token expired. This only affects auto-updates, the agent still runs. Contact Savas for a token update.

### "fatal: not a git repository"

The installation folder is not a proper git clone. This usually means it was installed from a zip. Contact Savas for a fresh reinstall.

### Config.json missing

Create it by running:
```
cat > ~/linkedin-agent-2/clients/max_rooney/config.json << 'EOF'
{
  "agent_name": "Max",
  "telegram_bot_token": "YOUR_BOT_TOKEN",
  ...
}
EOF
```
Contact Savas for the exact config values.

### Two Chrome windows opening / browser interfering with itself

Stop the agent, then remove the browser lock files:
```
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
rm -f ~/linkedin-agent-2/clients/max_rooney/linkedin_profile/SingletonLock
rm -f ~/linkedin-agent-2/clients/max_rooney/linkedin_profile/SingletonSocket
sleep 3
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/digital.rooney.max_rooney.plist
```

## THE TELEGRAM APPROVAL WORKFLOW

When a LinkedIn lead replies, the agent sends a message to the Telegram group like:

```
🎖 Max
📩 John Smith says:
"Hi, interested in learning more!"

💬 Proposed reply:
"Hey John, great to hear from you! ..."

[Approve] [Edit] [Skip]
```

- **Approve** — sends the message to LinkedIn immediately (after a 5 minute delay)
- **Edit** — lets you type a different reply
- **Skip** — dismisses this conversation until the lead sends a new message

If you don't see the approval, scroll up in the Telegram group — it may have been sent earlier.

## AGENT STATUS INDICATORS

When asked "is my agent running?":
1. Check with `launchctl list | grep rooney`
2. A PID number in the first column = running
3. A dash (-) in the first column = not running

When asked "is it working?":
1. Check the log with `tail -20 ~/linkedin-agent-2/clients/max_rooney/agent.log`
2. Look for recent "Tick" entries with timestamps
3. If the last tick was more than 10 minutes ago, something is wrong

---

## IMPORTANT NOTES

- The agent polls every 5 minutes (300 seconds), so there is always up to a 5 minute delay before a message is picked up
- Approved messages are sent after a 5 minute delay (to look natural)
- The agent only processes the most recent 15 conversations per tick
- After you skip a conversation, the agent ignores it until the lead sends a new message
- The agent runs 24/7 as long as the Mac is on and not in deep sleep (use caffeinate to prevent sleep)
- Never run the agent on two computers for the same LinkedIn account at the same time
